# Публичный сайт покупателя

Сайт без пароля владельца: покупатель выбирает услугу, вставляет факты, оплачивает и получает текст по секретной ссылке. Кабинет владельца остаётся закрытым.

## Страницы

| Адрес              | Что там                                                                                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                | Витрина: опубликованные услуги с ценой в рублях, фильтр по задачам, «Как это работает», «Уже заказывали?» (ссылки из этого браузера).                                     |
| `/services/[slug]` | Услуга: что получите, пример, форма заказа, «Подставить пример», согласие о правах на текст, кнопка «Перейти к оплате, 490 ₽».                                            |
| `/order/[token]`   | Заказ по секретной ссылке: шаги, оплата, результат, «Скопировать», «Скачать .txt», «Скопировать ссылку». Статус обновляется сам каждые 4 секунды и замирает на финальном. |
| `/terms`           | Короткие условия тестового магазина или ссылка из `PUBLIC_TERMS_URL`.                                                                                                     |

Тестовый режим сказан один раз: полоской над шапкой. Покупатель не видит агентов, стратегий, версий, попыток, кодов ошибок и чужих заказов.

На витрине только продукты, которые владелец опубликовал (`products.visibility='public'`). Названия и обещания для покупателя лежат в `core/public-catalog.ts` (`buyerCopy`), собственная страница продукта (`products.page`) их перекрывает. Пример «вы прислали / мы сделали» показывается, только если контрольный пример прошёл проверку и сделан настоящей моделью, не демо-провайдером.

## API без сессии

| Запрос                                      | Лимит на адрес |
| ------------------------------------------- | -------------- |
| `GET /api/public/catalog`                   | 120 в минуту   |
| `GET /api/public/services/[slug]`           | 120 в минуту   |
| `POST /api/public/orders`                   | 10 в час       |
| `GET /api/public/orders/[token]`            | 120 в минуту   |
| `POST /api/public/orders/[token]/pay`       | 20 в час       |
| `GET /api/public/orders/[token]/result.txt` | 60 в минуту    |

Сверх лимита ответ 429. Общий предел публичных заказов в сутки (UTC) задаёт `PUBLIC_ORDERS_PER_DAY` (30 по умолчанию), сверх него 409 `PUBLIC_ORDERS_LIMIT`. На паузе фермы заказы не принимаются.

`server/middleware/security.ts` открывает только этот список путей. Всё остальное под `/api` по-прежнему требует сессию владельца, проверка Origin, JSON и размера тела действует и на публичные POST.

## Секретная ссылка

- Токен 43 символа (256 бит). В базе только `sha256(token)` в `orders.access_token_hash`.
- Токен выводится из случайного `requestKey` браузера и секрета сервера, поэтому повтор того же запроса (двойной клик, обрыв связи) возвращает тот же заказ и ту же ссылку. Другой текст с тем же ключом даёт 409.
- Неизвестный, искажённый и заменённый токен дают одинаковый 404. 50 промахов за 10 минут пишут событие аудита `public_token_probe` без адресов.
- Владелец может заменить утёкшую ссылку: `POST /api/orders/[id]/relink` (только с сессией). Старая ссылка сразу перестаёт открываться. Кнопки в кабинете для этого пока нет.

## Адрес покупателя для лимитов

В базу попадает только HMAC адреса (`rate_limits.key`, `orders.client_key`). За обратным прокси на частном адресе (Caddy в compose) адрес берётся из последней записи `X-Forwarded-For`. Серверный рендер страниц вызывает API изнутри; middleware передаёт туда адрес покупателя с подписью, подделанный снаружи заголовок игнорируется. В `nuxt dev` у запросов нет сокета, и все считаются одним адресом `internal`; в собранном сервере адрес настоящий (проверено).

## Проверки

- `tests/integration/public-orders.test.ts`: путь в sandbox через настоящий middleware и обработчики, изоляция (кабинет 401, чужая ссылка 404, чужой Origin 403), лимиты 429, дневной предел 409, пауза, аудит перебора, замена ссылки.
- `tests/integration/public-sepolia.test.ts`: Sepolia на подменённом RPC.
- `tests/unit/public-orders.test.ts`, `rate-limit.test.ts`: токены, суммы, статусы для покупателя, ключи лимитов.
- Playwright: весь путь на 1440 и 390 в sandbox и с оплатой через anvil, кнопка кошелька с подставным EIP-1193 провайдером.

## Что не сделано

- Писем покупателю нет: ссылка показывается на экране и хранится в браузере.
- Правовые тексты и реквизиты продавца задаёт владелец (`PUBLIC_SELLER`, `PUBLIC_CONTACT`, `PUBLIC_TERMS_URL`); без них сайт закрыт от индексации.
- Кнопки замены ссылки в кабинете нет (есть API).
