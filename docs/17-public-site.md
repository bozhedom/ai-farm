# Публичный сайт покупателя

Сайт без пароля владельца: покупатель выбирает услугу, вставляет факты, оплачивает и получает текст по секретной ссылке. Кабинет владельца остаётся закрытым.

## Страницы

| Адрес              | Что там                                                                                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                | Витрина: опубликованные услуги с ценой в рублях, фильтр по задачам, «Как это работает», «Уже заказывали?» (ссылки из этого браузера).                                     |
| `/services/[slug]` | Услуга: что получите, пример, форма заказа, «Подставить пример», согласие о правах на текст, кнопка «Перейти к оплате, 490 ₽».                                            |
| `/order/[token]`   | Заказ по секретной ссылке: шаги, оплата, результат, «Скопировать», «Скачать .txt», «Скопировать ссылку». Статус обновляется сам каждые 4 секунды и замирает на финальном. |
| `/terms`           | Короткие условия тестового магазина или ссылка из `PUBLIC_TERMS_URL`.                                                                                                     |

Тестовый режим сказан один раз: полоской над шапкой. Покупатель не видит агентов, стратегий, версий продукта, признака демо, попыток, кодов ошибок и чужих заказов: публичный API этих полей не отдаёт.

В sandbox кнопка «Оплатить (тест)» видна покупателю только при `PUBLIC_SANDBOX_PAY=true`. Это настройка для локального показа: каждый оплаченный заказ тратит бюджет модели. По умолчанию она выключена, покупатель видит «оплату подтверждает продавец», а владелец подтверждает тестовую оплату в кабинете.

На витрине только продукты, которые владелец опубликовал (`products.visibility='public'`). Демо-продукт (сделанный демо-провайдером) на стенде с настоящей моделью заказать нельзя: заказ по его адресу даёт тот же 404, что и неизвестная услуга. Названия и обещания для покупателя лежат в `core/public-catalog.ts` (`buyerCopy`), собственная страница продукта (`products.page`) их перекрывает. Пример «вы прислали / мы сделали» показывается, только если контрольный пример прошёл проверку и сделан настоящей моделью, не демо-провайдером.

## API без сессии

| Запрос                                      | Лимит на адрес |
| ------------------------------------------- | -------------- |
| `GET /api/public/catalog`                   | 120 в минуту   |
| `GET /api/public/services/[slug]`           | 120 в минуту   |
| `POST /api/public/orders`                   | 10 в час       |
| `GET /api/public/orders/[token]`            | 120 в минуту   |
| `POST /api/public/orders/[token]/pay`       | 20 в час       |
| `GET /api/public/orders/[token]/result.txt` | 60 в минуту    |

Сверх лимита ответ 429. Пределы в сутках UTC:

- `PUBLIC_ORDERS_PER_DAY` (30): заказы за день, которые ещё ждут оплату или оплачены. Просроченные неоплаченные место освобождают. Сверх предела 409 `PUBLIC_ORDERS_LIMIT`.
- `PUBLIC_PAID_ORDERS_PER_DAY` (10): оплаченные за день заказы. Когда предел набран, новые заказы не принимаются (`PUBLIC_ORDERS_LIMIT`), а витрина пишет, что заказы закончились.
- `PUBLIC_OPEN_ORDERS_PER_CLIENT` (2): неоплаченных заказов на один адрес покупателя одновременно, сверх 409 `PUBLIC_OPEN_ORDERS_LIMIT`.

На паузе фермы заказы не принимаются.

**Бюджет модели.** Неоплаченный публичный заказ бюджет не держит: его резерв создаётся с нулевым пределом и любой вызов модели по нему запрещён. Резерв `ORDER_RESERVE_KOPECKS` берётся в момент подтверждения оплаты, в той же транзакции, что и постановка в работу. Если денег на день или месяц нет либо набран `PUBLIC_PAID_ORDERS_PER_DAY`:

- кнопка sandbox у покупателя отвечает 409 `PUBLIC_CAPACITY_REACHED`, оплата не проходит;
- подтверждённый перевод Sepolia (или sandbox из кабинета) переводит заказ в `manual_review` с причиной `BUDGET_BLOCKED` / `PAID_ORDERS_LIMIT`, исполнение не запускается. Покупатель видит «Оплата получена, но сегодня не успеем», владелец видит причину в карточке заказа.

Новый заказ не принимается (`BUDGET_BLOCKED`), если бюджета на его исполнение сейчас нет, но и тогда ничего не резервируется.

`server/middleware/security.ts` открывает только этот список путей. Всё остальное под `/api` по-прежнему требует сессию владельца, проверка Origin, JSON и размера тела действует и на публичные POST. Middleware смотрит на сырой путь, как роутер: путь под `/api` или `/order` с `\`, `%2e`, `%2f`, `%5c` (в любом регистре), `//`, `/./` или `/../` получает 400 `BAD_PATH`. Тело, которое не разбирается как JSON, даёт 400 `INVALID_INPUT`. `result.txt` отвечает и на HEAD.

Ответы API и страницы `/order/**` идут с `Cache-Control: no-store`. Страницы заказа получают CSP: скрипты, стили, картинки и запросы только с этого сайта, без фреймов (`script-src 'self' 'unsafe-inline'`, встроенный скрипт нужен Nuxt для гидрации).

**Индексация.** Все ответы идут с `X-Robots-Tag: noindex, nofollow`. При `PUBLIC_INDEXING=true` (сервер не стартует без `PUBLIC_SELLER`, `PUBLIC_CONTACT` и `PUBLIC_TERMS_URL`) заголовок снимается только с `/`, `/services/[slug]` и `/terms`; страницы заказов, кабинет и API остаются закрыты.

## Секретная ссылка

- Токен 43 символа (256 бит). В базе только `sha256(token)` в `orders.access_token_hash`.
- Токен выводится из случайного `requestKey` браузера и секрета сервера, поэтому повтор того же запроса (двойной клик, обрыв связи) возвращает тот же заказ и ту же ссылку. Другой текст с тем же ключом даёт 409. Сам ключ в базе не лежит: `orders.request_key` хранит `sha256:<hex>` (миграция 021 перевела прежние значения), так что из базы и `SESSION_SECRET` ссылку не восстановить.
- Страница заказа проверяет формат токена до любых запросов: искажённая ссылка сразу показывает «Такого заказа нет».
- Неизвестный, искажённый и заменённый токен дают одинаковый 404. 50 промахов за 10 минут пишут событие аудита `public_token_probe` без адресов.
- Владелец может заменить утёкшую ссылку: `POST /api/orders/[id]/relink` (только с сессией). Старая ссылка сразу перестаёт открываться. Кнопки в кабинете для этого пока нет.

## Адрес покупателя для лимитов

В базу попадает только HMAC адреса (`rate_limits.key`, `orders.client_key`). IPv6 считается по сети /64, IPv4 в виде `::ffff:` как обычный IPv4. По умолчанию адрес покупателя это адрес сокета, `X-Forwarded-For` игнорируется. С `TRUST_PROXY=true` и только от прокси на частном адресе адрес берётся из последней записи `X-Forwarded-For`; `compose.edge.yaml` включает это для Caddy. Серверный рендер страниц вызывает API изнутри; middleware передаёт туда адрес покупателя с подписью, подделанный снаружи заголовок игнорируется. В `nuxt dev` у запросов нет сокета, и все считаются одним адресом `internal`; в собранном сервере адрес настоящий (проверено).

## Проверки

- `tests/integration/public-orders.test.ts`: путь в sandbox через настоящий middleware и обработчики, изоляция (кабинет 401, чужая ссылка 404, чужой Origin 403), лимиты 429, дневной предел 409, пауза, аудит перебора, замена ссылки.
- `tests/integration/public-sepolia.test.ts`: Sepolia на подменённом RPC, включая перехват чужого перевода и hash, которого нет в сети.
- `tests/integration/public-hardening.test.ts`: бюджет только после оплаты, отказ при нехватке бюджета и дневном пределе оплат, кнопка sandbox под флагом, два открытых заказа на адрес, `TRUST_PROXY`, хеш ключа запроса, сырые пути, битый JSON, HEAD.
- `tests/unit/public-orders.test.ts`, `rate-limit.test.ts`, `public-hardening.test.ts`: токены, суммы, статусы для покупателя, ключи лимитов, IPv6 /64, разбор путей.
- Playwright: весь путь на 1440 и 390 в sandbox и с оплатой через anvil, кнопка кошелька с подставным EIP-1193 провайдером.

## Что не сделано

- Писем покупателю нет: ссылка показывается на экране и хранится в браузере.
- Правовые тексты и реквизиты продавца задаёт владелец (`PUBLIC_SELLER`, `PUBLIC_CONTACT`, `PUBLIC_TERMS_URL`); без них `PUBLIC_INDEXING` включить нельзя и сайт закрыт от индексации.
- Кнопки замены ссылки в кабинете нет (есть API).
