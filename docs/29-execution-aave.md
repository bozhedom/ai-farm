# Исполнение Aave V3

Сервер умеет размещать USDC в пуле Aave V3 и возвращать их на тот же кошелёк. Заимствований, внешних переводов и обмена токенов нет. Поддержаны Ethereum, Sepolia и отдельный локальный Anvil. Разработка и проверка этого блока выполняются локально; на VPS он не опубликован.

## Как работает цикл

На вход выделяется до половины капитала направления. Сервер проверяет кошелёк, резерв и ставку, при необходимости обнуляет старое разрешение, выдаёт разрешение на точную сумму и вызывает `supply`. Каждый шаг имеет отдельную запись и транзакцию. Адрес получателя всегда совпадает с адресом подписанта.

Срок размещения, команда закрытия или ограничение убытка запускают `withdraw`. Результат в USDC — подтверждённый возврат минус размещённая сумма. Комиссии сети сохраняются отдельно в ETH; итог в USDC не является прибылью после оплаты газа. Проценты в Demo/Live определяются по фактическим aToken и событиям пула. Paper использует виртуальное начисление по публичной ставке на момент входа.

Подписанная транзакция, её hash и nonce сохраняются до отправки. Повтор использует те же байты. Успех подтверждается только после проверки сети, адресов, canonical block, числа подтверждений и точного события контракта. Неопределённый результат не создаёт новую транзакцию с другим nonce. Остаток aToken сохраняется в учёте; после ограниченного числа попыток его возврата операция требует проверки.

## Локальная проверка без денег

```bash
docker run -d --name farm-aave-local-execution -p 127.0.0.1:18550:8545 --entrypoint anvil ghcr.io/foundry-rs/foundry:v1.3.5 --host 0.0.0.0 --chain-id 11155111 --block-time 1
npx tsx scripts/execution-aave-local.ts
```

Если контейнер уже запущен, повторять первую команду не нужно. Скрипт принимает только локальный Anvil, разворачивает тестовые контракты и выдаёт тестовому аккаунту 1000 единиц токена. Это ERC20/Pool fixture из `tests/fixtures/aave`, а не развёрнутый протокол Aave и не настоящие USDC. Проценты в fixture не начисляются.

Настройки сохраняются в `.secrets/execution-aave-demo.json` с правами `0600`. Файл содержит `config` и публичный тестовый ключ Anvil в поле `privateKey`. Для отдельного процесса приложения передайте `JSON.stringify(config)` в `EXECUTION_DEFI_DEMO_CONFIG`, а `privateKey` — в `EXECUTION_DEFI_DEMO_PRIVATE_KEY`. Не выводите файл целиком в журнал. Основной `.env` скрипт не меняет. Повторный запуск проверяет существующие контракты, не сбрасывает кошелёк и историю.

В тестах проверены точное разрешение, размещение и возврат, потеря ответа после отправки, ожидание подтверждений, повтор без двойного исполнения, конфликт nonce, неверные контракты, долг и остатки. Контракты fixture собраны solc 0.8.30; тест сверяет хеш исходника. Эти проверки подтверждают локальный механизм, а не приёмку публичной сети Aave.

## Настройки публичной сети

Для Demo используются `EXECUTION_DEFI_DEMO_CONFIG` и `EXECUTION_DEFI_DEMO_PRIVATE_KEY`, для Live — соответствующие переменные с `LIVE`. Значение CONFIG — JSON или путь к JSON с публичной конфигурацией:

- `rpcUrl`: HTTPS RPC выбранной сети.
- `network`, `chainId`: `testnet`, `11155111` для Sepolia; `live`, `1` для Ethereum.
- `sender`: адрес отдельного кошелька, соответствующий приватному ключу.
- `pool`, `token`, `aToken`: для каждого адрес и `codeHash` исполняемого байткода. Для прокси также `implementation.address` и `implementation.codeHash`.
- `confirmations`: число подтверждений, не меньше серверного минимума.

Адреса сверяются с [официальным Aave Address Book](https://github.com/bgd-labs/aave-address-book). Хеши рассчитываются из `eth_getCode` для выбранной сети. Прокси проверяются по слотам EIP-1967 и [ZeppelinOS, используемому Circle](https://github.com/circlefin/stablecoin-evm/blob/master/contracts/upgradeability/UpgradeabilityProxy.sol). После обновления реализации старые пины блокируют новую отправку до проверки владельцем. Переносить адреса и хеши локального fixture в публичную сеть нельзя.

При первом запуске кошелёк должен иметь выделенный капитал USDC и ETH на газ, без долга и открытого размещения. Нужны соответствующий выбранной сети токен USDC с 6 знаками, ликвидный резерв и проверенные контракты. Пулы и токены не выбираются моделью. Ключ задаётся локально, не через интерфейс, репозиторий или переписку.

Live дополнительно требует явного разрешения, серверных проверок и завершённой приёмки Demo. Работа с настоящим Aave, восстановление на внешнем RPC и расходы реального газа ещё должны быть проверены с выбранным кошельком. L2, другие активы и безлимитные разрешения в этот исполнитель не входят.

Сигнатуры вызовов и событий соответствуют [Pool Aave V3](https://aave.com/docs/aave-v3/smart-contracts/pool) и [совместимому `ReserveDataLegacy`](https://github.com/aave/aave-v3-origin/blob/main/src/contracts/protocol/libraries/types/DataTypes.sol).
