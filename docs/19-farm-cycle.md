# Цикл фермы: идеи, продукты, клиенты, отчёт

Ферма работает сама по суткам UTC. Руководитель здесь это серверный код, а не модель: он раздаёт задачи, считает баллы и следит за бюджетом. Модели только отвечают по схемам; действия выполняет сервер.

## Как проходит день

1. **Задания.** Каждому из четырёх разведчиков сервер даёт тему из таксономии (`core/taxonomy.ts`: 18 отраслей, 36 тем). Сначала темы из отраслей агента, давно не разведанные; у разных агентов в один день разные темы и отрасли. В ленте: «Руководитель раздал задания: Разведчик А ищет на маркетплейсах, Б в общепите…».
2. **Разведка** (`scout`). Два поиска по серверным фразам темы (спрос и конкуренты), до 12 источников. Разведчик возвращает идею: аудитория, проблема, признаки спроса со ссылками только из выдачи, конкуренты, модель дохода, расходы, риски, быстрый тест и честная оценка «ферма сделает сама». Критик спорит. Повтор старой идеи (тот же отпечаток или сходство от 0,6) получает «на доработку».
3. **Отчёт** (`report:daily:<день>`), когда все разведки дня закончились. Сервер ставит статусы. Принята критиком и исполнима фермой: «принята». Принята, но нужна работа людей: «нужен человек» с планом запуска. Отклонена критиком: «отклонена». Балл 0..100 считает сервер. Модель «Руководитель» пишет короткий текст по серверным цифрам; если модель недоступна, отчёт сохраняется с цифрами.
4. **Сборка продукта.** Отчёт отправляет лучшие принятые идеи на исследование (`idea-research:<id>`, не больше `IDEA_PRODUCTS_PER_DAY` в день, по одной на тип услуги). Прежний конвейер проверяет шаблон и контрольный пример; при успехе продукт выходит на витрину: цена из серверного списка, страница (заголовок, кому, что получите, ограничения), ссылка на идею.
5. **Клиенты** (`lead:<день>:<продукт>`). Для продуктов на витрине сервер ищет публичные запросы и готовит отклики (не больше `LEAD_DRAFTS_PER_DAY` в день). Отклик проверяется: без почты, телефонов, @-упоминаний, чужих ссылок, скидок и гарантий; единственная ссылка ведёт на страницу продукта. Отправляет только человек.
6. **Отбор агентов** (`evolve`), когда у всех хватает идей. Подробно в [20-evolution.md](20-evolution.md).

Еженедельно, как и раньше, проходит денежная проверка (HOLD без продаж) и недельный отчёт руководителя.

## Очередь и ограничения

- Приоритет: заказы, отбор, отчёт, исследование, разведка, клиенты. Задания модели фермы идут по одному, даже при двух worker.
- Пауза, остановка и закрытый сезон останавливают новую работу фермы. Отбор идёт и на паузе (с решением «ждём»), но не после остановки.
- Задания по расписанию ждут, если расписание выключено. Кнопка «Найти идеи сейчас» (`POST /api/office/scout`) работает и без расписания.
- Платные провайдеры откладывают деньги под задачу (`SCOUT_RESERVE_KOPECKS`, `LEAD_RESERVE_KOPECKS`, `REPORT_RESERVE_KOPECKS`). Если кончился только дневной лимит, задача ждёт завтра. Бесплатные модели ничего не откладывают.
- Вчерашние неначатые разведки и поиски клиентов пропускаются, очередь не копится.

## Настройки владельца

`POST /api/office/settings`: разведок на агента в день (по умолчанию 1), поисков клиентов в день (4), отбор вкл/выкл, порог идей для отбора (6), отборов в день (1). Денежные лимиты меняются только в окружении сервера.

## Подготовка показа

`npm run demo:prepare -- --cycles 3 --min-ideas 2` прогоняет несколько циклов: разведка всеми агентами, отчёт, сборка продуктов, поиск клиентов, отбор с порогом 2 (после него порог возвращается). Работает на базе `*_test`, с `MODEL_PROVIDER=demo` или с флагом `--i-know-this-is-production`; на рабочей базе без флага отказывается. Демо-данные помечены `is_demo` и ссылаются только на example-домены. Чтобы на витрине было больше продуктов, временно поднимите `IDEA_PRODUCTS_PER_DAY` (до 12).

## Живая проверка (08.10, бесплатный OpenRouter и SearXNG)

База `farm_b_test`, модель `dots-studio/dots-3-note-preview:free`, поиск SearXNG на 127.0.0.1:8088, тема «Карточки товаров на Ozon и Wildberries».

- Разведка: 109 с. Поиск 12 источников с 11 доменов (13 с), идея 56 с, критик 39 с, 0 ₽. Обе роли один раз исправляли формат: разведчик сослался на URL не из выдачи, критик превысил 700 знаков. После исправления ответы прошли проверку.
- Идея «Сервис оптимизации карточек товаров для маркетплейсов на ИИ»: честно «нужен человек», шесть признаков спроса со ссылками на найденные сайты, конкуренты с ценами, план запуска. Критик дал «на доработку»: идея повторяет существующие сервисы и требует интеграций. Балл 63.
- Отчёт: 16 с, текст прошёл проверку. Слабое место: модель сослалась на идею по её id и предложила владельцу шаг для идеи «нужен человек», хотя статус был «на доработку».
- Первый прогон без продления аренды упал с `LEASE_LOST`: разведка длиннее двух минут аренды. Worker продлевает аренду сам; `demo:prepare` исправлен и тоже продлевает.

Сделать вывод о качестве идей по одной разведке нельзя. Спрос в выдаче поиска не доказывает продаж.
