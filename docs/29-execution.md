# Исполнение арбитража фандинга DeFi и прогнозов

Операции доступны в кабинете «Направления». С 20.10.2026 блок работает на продакшене Timeweb: автопилот запускает Paper-книги арбитража, фандинга и DeFi; Demo — только при наличии Demo-ключей. Live выключен по умолчанию и с 28.10.2026 открывается явным включением владельца (`EXECUTION_LIVE_ENABLED` и принятые треки) без обязательных Demo-циклов; прибыль не обещается ([34-launch-timeweb.md](34-launch-timeweb.md)). Предыдущий кабинет спота и модельный менеджер продолжают использовать свои счета и ограничения.

## Что исполняется

| Направление | Исполнитель                      | Поведение                                                                                                                                                                                                    |
| ----------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Арбитраж    | OKX, Bybit, Binance Spot, Bitget | Покупка и продажа на двух заранее пополненных счетах. Проверка стакана, тарифов и совпадения актива. Частичное исполнение компенсируется. Переводов между биржами нет.                                       |
| Фандинг     | Bybit                            | Оплаченный спот и противоположный perpetual с изолированной маржой и плечом 1. Выплаты сверяются с историей счёта. Закрытие при смене ставки, истечении срока, приближении ликвидации или команде владельца. |
| DeFi        | Aave V3                          | Разрешение на точную сумму USDC, внесение в пул и возврат на тот же кошелёк. Ethereum, Sepolia и локальный Anvil. Заимствований нет.                                                                         |
| Прогнозы    | Kalshi                           | Покупка обеспеченных контрактов по заданной оценке вероятности, продажа собственных контрактов и учёт фактического расчёта рынка. Отдельный subaccount. Polymarket пока остаётся источником наблюдений.      |

MEV, произвольные протоколы, стейкинг нативных монет, перемещение средств между площадками и создание кошельков моделью сюда не входят. Модельный менеджер не получил права на эти денежные действия.

## Локальный запуск

Нужны работающий PostgreSQL, настроенный локальный `.env` и зависимости проекта.

```bash
npm run build
npm run execution:local
```

Адрес: `http://localhost:3214/office/earnings`. Пароль владельца берётся из локального `.env`. Запускатель принимает только локальную БД, применяет миграции, поднимает кабинет на отдельном порту и обработчик новых операций. Существующие данные сохраняются. Он принудительно запрещает Live и не запускает дополнительные модельные задания. Остановка — Ctrl+C. После изменения кода сначала повторите сборку.

Для проверки подписанных транзакций без настоящих средств подготовьте [локальный Aave-стенд](29-execution-aave.md). Запускатель автоматически прочитает его настройки из `.secrets/execution-aave-demo.json`. Это тестовые контракты с интерфейсом пула и токена, не настоящий протокол Aave. В кабинете выберите «Фандинг и DeFi», «DeFi», «Тестовый счёт», задайте сумму и запустите. Дождитесь открытой позиции, затем нажмите «Закрыть позицию» и проверьте журнал.

В тренировке аккаунты не нужны. Источники котировок должны быть доступны. Пустой список сделок означает ожидание подходящих условий, а не обещанную сделку по расписанию. Для Kalshi требуется код события и собственная оценка вероятности; приложение не выдумывает прогноз вместо владельца.

## Подключения заказчика

Каждое направление и режим требуют отдельных счетов. Нельзя подключать счёт обычного спотового бота ещё и к фандингу или арбитражу. Система проверяет доступную идентичность счёта и сохраняет его владельца в БД. Не торгуйте вручную на выделенных счетах и не меняйте средства во время работы: расхождение требует сверки.

Арбитраж: две биржи, отдельные ключи чтения и спотовой торговли без вывода, ограничения IP для Live, USDT и запас одних и тех же монет на обоих счетах. Ключи задаются в `EXECUTION_ARBITRAGE_<EXCHANGE>_<DEMO|LIVE>_API_KEY/SECRET/PASSPHRASE`. Passphrase нужен OKX и Bitget. Для реальных и демо счетов отдельно заполните `EXECUTION_ARBITRAGE_ASSETS`: JSON-массив с `symbol`, проверенным `identity` токена и списком `exchanges`. Одинакового тикера недостаточно. Начальная стоимость монет не должна превышать половину бюджета; остаток покрывает покупки. Во время работы учитывается и изменение стоимости заранее внесённых монет.

Фандинг: отдельный Bybit UTA2, isolated margin, one-way, leverage 1, без старых позиций и сторонних активных заявок. Ключи `EXECUTION_FUNDING_BYBIT_<DEMO|LIVE>_API_KEY/SECRET`, права чтения и спота/деривативов, без вывода. Настройки аккаунта владелец задаёт сам: бот не переключает плечо или режим. Нужны USDT одновременно на покупку спота, маржу и комиссии. Реальный минимум зависит от выбранной монеты и лота фьючерса.

DeFi: отдельный кошелёк, USDC и ETH для газа, HTTPS RPC, проверенные адреса пула, токена и aToken, хеши кода и реализаций прокси. Поля и проверка описаны в [инструкции Aave](29-execution-aave.md). Ключ хранится только в окружении процесса. Результат в USDC не включает стоимость ETH: газ показан отдельно. Защита от просадки USDC учитывает количество токенов, а не изменение курса стейблкоина к доллару.

Kalshi: допустимый по правилам площадки аккаунт, отдельный subaccount с номером от 1, USD, API key ID, приватный ключ подписи и member/user ID. Переменные: `EXECUTION_PREDICTION_KALSHI_<DEMO|LIVE>_KEY_ID/PRIVATE_KEY/ACCOUNT_ID/SUBACCOUNT`. Ключ должен быть ограничен этим subaccount и правами `read` и `write::trade`. Для Live дополнительно `EXECUTION_PREDICTION_KALSHI_ELIGIBILITY_CONFIRMED=true` и действующая проверка местоположения со стороны API. На пустом счёте user ID задаётся владельцем; затем сверяется с ордерами. Это ограничение первоначальной идентификации, не проверка владения произвольным ID.

Россия указана в запрещённых юрисдикциях [Kalshi Member Agreement](https://kalshi.com/docs/kalshi-member-agreement.pdf). Российскому резиденту нельзя обещать этот реальный запуск. Код не обходит ограничения площадки. Доступность Demo также зависит от самой площадки.

Никакие ключи, seed-фразы или документы клиента не передаются в чат и не сохраняются в Git. Деньги заказчик вносит на свои счета самостоятельно.

## Условия допуска и остановки

Paper, Demo и Live используют разные портфели, операции и результаты. Тестовая прибыль не учитывается как настоящая выручка. После первого запуска капитал и подключения закрепляются в БД. Условия работы можно изменить только на паузе, после полного завершения операций; история, результат и риск сохраняются. Прежние Demo циклы с другими параметрами не дают допуск новой конфигурации.

Фандинг открывает пару только за 5–60 минут до ближайшей выплаты и только если три последние выплаченные ставки положительные. Падение прогнозной ставки до нуля и ниже закрывает пару только после первой выплаты с момента открытия шорта (плюс 2 минуты на её учёт): раньше пара платила четыре комиссии и закрывалась, не получив ни одной выплаты. Выходы по убытку, близости ликвидации, команде владельца и сроку удержания работают как прежде. Параметры: `FUNDING_STRATEGY` в `core/execution/drivers/funding.ts`. Прибыльность новой схемы не подтверждена.

На один цикл арбитража или фандинга резервируется не более 20% капитала, на контракт прогнозов — не более 10%, на размещение Aave — не более 50%. Нижний размер ордера дополнительно ограничен площадкой. Дневной предел убытка — 2%, просадка от максимума — 10%. Фандинг также контролирует запас до ликвидации. Ограничения вынесены в `EXECUTION_POLICY`, а не в промпт.

«Пауза» запрещает новые циклы; принятые операции продолжают контролироваться. «Закрыть позицию» завершает текущую позицию и не открывает следующую. Неопределённое исполнение, остаток ниже минимального лота, изменение контракта или расхождение баланса требуют проверки. Остановка не обещает мгновенного выхода при недоступной площадке или отсутствии ликвидности.

Для Live в обычном worker нужны `EXECUTION_LIVE_ENABLED=true`, имя направления в `EXECUTION_LIVE_ACCEPTED_TRACKS`, отдельные ключи и пройденная проверка Demo. Проверяются минимум пять полных подтверждённых циклов за период от суток с теми же параметрами и отсутствие незавершённых неопределённых операций. Секреты сами по себе запуск не разрешают. Локальный запускатель `execution:local` не позволяет включить Live даже при таком `.env`.

## Хранение и восстановление

`core/execution` отделён от `core/trading`. `execution_portfolios` хранит капитал и риск, `execution_operations` — циклы, `execution_legs` — отдельные заявки, `execution_cashflows` — выплаты, `execution_accounts` — привязку счёта. Общий реестр `execution_account_owners` не позволяет использовать одну идентичность нескольким книгам учёта.

Подготовленное поручение сохраняется до отправки, а признак отправки — до сетевого вызова. При потере ответа бирже не отправляется новый ордер. Для EVM допустим повтор тех же подписанных байтов с теми же hash и nonce; новый nonce вместо неизвестной транзакции запрещён. Уникальность nonce защищена БД и общей блокировкой обработчика. Полученный результат и освобождение резерва записываются транзакционно.

Все суммы считаются через BigInt и точные десятичные строки. Подписанные транзакции и внутренние запросы не выдаются браузеру или модели. В кабинете доступны только сумма, исполнение, комиссия, состояние и публичный идентификатор операции.

## Проверки и внешняя приёмка

Unit и интеграционные тесты покрывают полные циклы и сбои: частичное исполнение, комиссии, неизвестную заявку, перезапуск, повторное закрытие, общий счёт, неизменяемый бюджет, nonce и безопасный DTO. Anvil проверяет настоящие локальные подписи, receipt и события тестовых контрактов. Полные команды проекта: typecheck, unit, integration, build, format:check и `npm run test:crypto`; кабинет проверяется Playwright.

До настоящих средств остаются приватные Demo API на аккаунтах заказчика, публичная тестовая сеть Aave с выбранными контрактами/RPC, длительное наблюдение, внешняя сверка выписок и проверка восстановления. Успешные mocks и локальный Anvil не заменяют эту приёмку. Прибыльность стратегий не подтверждена.

Источники API: [Bybit orders](https://bybit-exchange.github.io/docs/v5/order/create-order), [Bybit transaction log](https://bybit-exchange.github.io/docs/v5/account/transaction-log), [Bybit Demo](https://bybit-exchange.github.io/docs/v5/demo), [Aave Pool](https://aave.com/docs/aave-v3/smart-contracts/pool), [Kalshi Create Order V2](https://docs.kalshi.com/api-reference/orders/create-order-v2), [Kalshi fixed-point migration](https://docs.kalshi.com/getting_started/fixed_point_migration).
