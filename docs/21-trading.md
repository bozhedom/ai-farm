# Автономная спотовая торговля

Объём согласован владельцем 12.10.2026: единый кабинет для **OKX, Bybit, Binance Spot и Bitget UTA**. Одно подключение каждой биржи, с отдельными Paper/Demo/Live портфелями. У каждой биржи свои агенты, баланс, сделки, журнал, поколения и история риска. Средства остаются на аккаунтах заказчика. Старые продукты, заказы, платежи и аудит студии сохранены.

## Что получить от заказчика

Для демонстрации бумаги аккаунты и деньги **не нужны**. Достаточно запущенного сервера с доступом к публичным API. Кнопка «Запустить тренировку» запускает четыре независимых эксперимента; недоступная биржа показывает ошибку, остальные продолжают работать.

Для проверки исполнения и последующего запуска нужны:

1. Выбранные биржи и страна регистрации аккаунтов. Можно начать с одной; четыре аккаунта создавать необязательно. Заказчик сам открывает и верифицирует аккаунты, доступные ему по правилам соответствующей биржи.
2. На каждой выбранной бирже — выделенный торговый аккаунт/субаккаунт для приложения. Без других ботов, ручных сделок, займов и деривативов. Перед первым запуском на выделенном аккаунте должны быть только USDT; другие ненулевые активы не игнорируются.
3. Отдельный **демо-ключ** и 100 тестовых USDT для проверки. Binance использует Spot Testnet, остальные — Demo Trading. Обычные реальные ключи не подходят для демо.
4. Отдельный **реальный API-ключ**, права чтения и нужной торговли, без вывода, с привязкой к статическому IP сервера. Парольная фраза API нужна у OKX и Bitget. Секреты заказчик/администратор вводит в окружение сервера; через чат их передавать не нужно.
5. Начальный бюджет, выбранный заказчиком и распределённый между нужными биржами. Сумма может быть меньше или больше 100 USDT: это был пример, а не потолок. Для включённой биржи текущим стратегиям нужно минимум 20 USDT, для отключённой укажите 0. Владелец сам пополняет именно торговые счета на выделенные суммы. Приложение не переводит средства. USD и USDT не тождественны.
6. Постоянно работающий сервер со статическим IP, доступом к разрешённым API, синхронизацией времени, PostgreSQL, web и worker. Для внешнего кабинета — HTTPS и домен. Сервер должен находиться там, где биржа допускает его использование с данным аккаунтом.
7. Принятие текущих ограничений: динамический отбор спотовых пар к USDT, без плеча, ввод/вывод вручную; прибыль не гарантируется. Доступ к реальной торговле требует результатов бумаги и успешного демо-цикла **на той же бирже**.

Разрешения Trade у OKX и UTA у Bitget шире отдельных спотовых операций. Это не ключи, технически ограниченные только покупкой BTC/ETH: выделенный аккаунт и минимальные права обязательны. Серверный код приложения умеет только разрешённые спотовые операции; модели не получают ключи, доступ к API или инструменты торговли.

`OKX_API_HOST` и `BYBIT_API_HOST` выбираются из фиксированного списка официальных доменов в `core/config.ts`, в соответствии с регионом регистрации. Demo Bybit всегда использует отдельный демо-хост. Binance реализован для глобального Spot API `api.binance.com`; Binance.US и другие самостоятельные региональные продукты не поддержаны. Bybit EU также не является этим адаптером. Bitget использует `api.bitget.com`. Если подходящего региона нет или биржа запрещает доступ, это подключение не запускают.

Bybit Demo и Binance Testnet не предоставляют все интерфейсы проверки прав реального ключа. Там проверяются отдельный хост/ключ, счёт, баланс, комиссии и фактический тестовый цикл. Проверки прав и IP реального ключа выполняются перед live. Binance Testnet может сбрасывать тестовые балансы и историю: расхождение остановит портфель; автоматически стирать журнал ради продолжения нельзя. Смена Bybit Demo ключа также меняет идентификатор тестового подключения и требует отдельной сверки.

## Установка и запуск

Новая установка: `npm ci`, `npm run setup`, `docker compose --profile app up -d --build`. `setup` сохраняет существующие настройки. Полный список переменных есть в `.env.example`. По умолчанию `WORKSPACE_MODE=trading`, `TRADING_LIVE_ENABLED=false`; модель и поиск торговому циклу не нужны.

После изменения окружения пересоздайте web и worker. Миграции применяются `npm run db:migrate` или при старте web. **При обновлении со старой версии с одной биржей сначала остановите прежний worker и сделайте проверенную резервную копию**, затем обновите web с миграциями и запустите новый worker. Старый код с выборкой только по режиму нельзя оставлять рядом со схемой на несколько бирж. Миграция 027 сохраняет все старые данные как OKX и оставляет его прежний live-бюджет; новым биржам выделяется 0 реальных USDT.

1. Откройте `/` или `/office/trading`, войдите с `OWNER_PASSWORD`. На главном экране показаны общий результат и список бирж. Нажмите на биржу: откроются «Результат», «Стратегии», «История» и «Подключение». Кнопка «Все биржи» возвращает к списку. Режим выбирается сверху; его переключение ничего не запускает. В справке «Как это работает» объяснён порядок запуска. Бумага, демо и реальные деньги в общей сумме не смешиваются.
2. В режиме **«Тренировка»** нажмите «Запустить тренировку» либо запустите выбранную биржу отдельно. Каждая получает четыре агента и 100 виртуальных USDT. Это 400 виртуальных USDT на четыре биржи, а не 400 реальных. Котировки берутся непосредственно с соответствующей биржи.
3. Для каждой выбранной биржи настройте демо-счёт и ключи на сервере. В режиме **«Тест биржи»**, разделе «Подключение» проверьте связь, затем запустите **«Проверить покупку и продажу»**. Цикл покупает и продаёт до 10 тестовых USDT, сверяет баланс и останавливается. Нужны 100 свободных тестовых USDT и отсутствие других активов перед первой инициализацией.
4. В режиме «Реальная торговля» откройте «Бюджет на биржи» на главном экране или в «Подключении» выбранной биржи. Укажите целую сумму USDT для каждой биржи и сохраните. Это план, он не перемещает деньги и не запускает торговлю. После первого реального запуска бюджет соответствующего портфеля фиксируется; остановка не сбрасывает риск и не позволяет повторно выделить уже работающие деньги.
5. Для live добавьте реальные ключи, пополните торговые счета по плану и включите `TRADING_LIVE_ENABLED=true` на сервере. Для **каждой** биржи необходимы прибыльный бумажный кандидат не моложе 7 дней с минимум 20 закрытыми позициями и просадкой до 8%, завершённый демо-цикл и недавняя проверка подключения. Подготовка может занять больше семи дней или не дать подходящего кандидата.
6. Подтвердите запуск выбранной биржи точной фразой из формы, например `ТОРГОВАТЬ 25 USDT НА BYBIT`. Фраза включает биржу и текущий бюджет. Один реальный агент получает только эту долю. Остаток USDT сверх бюджета учитывается отдельно и не увеличивает торговую сумму.

До первой инициализации реального портфеля подключённый капитал показан как 0, плановый бюджет — отдельно. После инициализации показывается оценка активов портфеля, а не полный баланс личного аккаунта. График содержит сохранённые наблюдения последних суток. Комиссии включены в результат; сервер, налоги и прочие расходы владельца — нет.

Проверка без заявок, без инициализации портфеля и изменения состояния БД:

```bash
npm run trading:check -- paper okx
npm run trading:check -- paper bybit
npm run trading:check -- paper binance
npm run trading:check -- paper bitget
# После настройки отдельных тестовых ключей:
npm run trading:check -- demo bybit
# После настройки реального ключа; эта команда тоже не торгует:
npm run trading:check -- live bybit
```

Браузер можно закрыть, сервер и worker должны оставаться включёнными. `WORKSPACE_MODE=trading` отключает исследования старой студии и продолжает выполнять принятые заказы. `WORKSPACE_MODE=studio` возвращает прежнее расписание. История студии доступна в `/office/overview`, витрина — `/storefront`.

## Стратегии и отбор

Три серверные стратегии: возврат к средней, следование тренду и пробой диапазона. В бумажном составе до четырёх агентов: два варианта возврата к средней, тренд и пробой. Монеты назначает разведчик; фиксированного списка BTC/ETH нет. При одной подходящей монете стартуют два агента, при отсутствии кандидатов портфель ждёт в USDT. Сигналы используют закрытые минутные свечи и исполнимые bid/ask. Исполнение на бумаге учитывает доступную глубину, неблагоприятное проскальзывание до 0,1% и комиссию 0,1%. Это симуляция, а не гарантированная цена реальной сделки. Агент без сигнала ждёт.

Отбор идёт отдельно на каждой бирже. Каждые сутки проверяется поколение: минимум 7 дней и 20 закрытых позиций у каждого, прибыльная верхняя половина состава с просадкой не выше 8% и преимуществом перед остальными. При открытых позициях или недостатке данных отбор ждёт. Законченное поколение архивируется, создаётся столько же потомков лидеров: половина с прежними параметрами, половина с ограниченной мутацией. Капитал сохраняется, статистика потомков начинается заново. Это эвристика, не доказательство будущей доходности.

Раз в сутки реальный агент может быть заменён более сильным зрелым бумажным кандидатом **с этой же биржи**, только при полностью закрытой позиции и отсутствии незавершённых ордеров. Требуются другие параметры и преимущество оценки минимум 0,5 п.п.; оценка — реализованная доходность минус максимальная просадка. Закрытая прибыль не скрывает текущий убыток открытых активов. Предыдущий агент архивируется; остаток денег, общий пик и дневная история риска сохраняются. Зрелые родители последнего бумажного поколения также доступны для допуска.

## Лимиты и управление

- Начальный бюджет live задаёт владелец, минимум 20 USDT на включённую биржу. Пример 100 USDT не ограничивает общий бюджет или сумму на одной бирже. Перераспределение до первого запуска выполняется одной транзакцией с блокировкой всех live-портфелей; при запуске проверяется фактический доступный баланс.
- Спотовые пары к USDT из свежего каталога и отбора выбранной биржи; спот, limit IOC, без плеча. Ввод, вывод, автоматическое заимствование, фьючерсы и переводы между биржами не реализованы.
- Покупка до 10 USDT с резервом комиссии; минимум 5 USDT и биржевые ограничения количества/стоимости. До 50% капитала в открытых позициях. Увеличение начального бюджета само по себе не увеличивает размер отдельного входа.
- На каждом портфеле отдельно: дневной убыток 2%, просадка от пика 10%, защитный выход позиции 3%; не более 40 заявок за UTC-сутки для допуска новых покупок, интервал обычных сделок 5 минут. Срочные защитные продажи проходят без задержки обычного входа.
- Комиссия до 0,25%, спред до 0,2%, проскальзывание до 0,1%. Устаревший или некорректный рынок блокирует новые заявки. Стопы выполняет worker: при разрыве связи или резком движении цена фактического выхода и величина убытка не гарантируются. Нативных биржевых стопов нет.
- **«Приостановить покупки»** блокирует покупки; управление открытой позицией и лимиты риска продолжаются. **«Продать купленные монеты»** прекращает входы и отправляет ограниченные продажи; исполнение зависит от рынка, маленькие остатки могут остаться.
- **«Остановить [биржа]»** прекращает новые заявки выбранного портфеля. **«Остановить всё»** останавливает все 12 портфелей без ожидания ответа бирж. Эти кнопки не продают активы. Уже отправленные заявки продолжают сверяться.

Продажа монет и отдельная остановка находятся в «Результате», блоке «Управление и ограничения». Параметры стратегий, данные заявки, технический журнал и настройка сервера раскрываются по запросу; аварийный общий стоп остаётся в шапке и доступен даже при ожидании ответа биржи.

Лимиты задаёт `core/policy.ts`, а не промпт. Деньги — целые значения масштаба 10¹⁸; API/БД границы используют строки. Ввод бюджета принимает целые USDT до `Number.MAX_SAFE_INTEGER` на биржу, без потери точности; итог по биржам складывается через BigInt. Это техническая граница представления числа. Виртуальные портфели и начальный план новой установки используют 100 USDT по умолчанию. Числовые токены стакана Bitget читаются из исходного JSON без округления через `Number`. Модели не вызываются в торговом цикле и не меняют лимиты.

Неопределённый ответ на отправку сохраняется как `unknown`. Повторной отправки того же намерения нет. Обработчик читает ордер по постоянному клиентскому ID, сверяет исполнения и комиссии. При доказанном отсутствии владелец проверяет историю биржи и использует точное подтверждение «ПРОВЕРЕНО НА БИРЖЕ»; сервер повторно проверяет отсутствие и баланс. Подмена аккаунта, ручные сделки или переводы вызывают остановку при расхождении. Смена ключа не является способом сбросить журнал.

У бирж отдельные фоновые циклы и блокировки по `exchange + mode`. Медленная или недоступная биржа не задерживает следующие циклы других. Внешние ключи не возвращаются в кабинет; управляющие API требуют сессию владельца и проверенный Origin. Одно подключение одной биржи не может списать деньги агента другой биржи: это защищено также внешними ключами PostgreSQL. CSV и журнал относятся к выбранным бирже и режиму.

## Разведчик монет и ротация (локальная версия 12.10)

Вкладка **«Рынок»** показывает полный найденный каталог пар к USDT, поиск и страницы списка, результаты фильтра, актуальные назначения и их историю. Каталог и расчёты изолированы по бирже и режиму. Число найденных пар зависит от текущего листинга и окружения биржи; приложение не считает любую существующую монету доступной для торговли.

Разведчик выполняется сервером без модели и платных вызовов. Каждые 5 минут он получает инструменты и суточные тикеры через публичные API. Отбирает активные пары с оборотом от 1 млн USDT/сутки, спредом до 0,2%, суточным диапазоном 1,5–30% и изменением до ±20%. Исключает известные стейблкоины, токены с плечом, ограничения биржи и известные листинги моложе суток. Это технический фильтр, не анализ капитализации, команды проекта, новостей или обещание роста. При отсутствии времени листинга возраст не выдумывается: для допуска всё равно нужны 120 непрерывных закрытых минутных свечей.

За проход подробно проверяются до 12 кандидатов, включая текущие подходящие пары, лидеров первичного рейтинга и очередную часть резерва. Резерв выбирается по времени последней подробной проверки, поэтому пары ниже рейтинга тоже получают проверку. Проверяются два часа свечей, диапазон движения 1–15%, отсутствие минутных скачков больше 5%, глубина не менее 100 USDT с каждой стороны в пределах 0,1% от лучшей цены и минимальный ордер. В резерве могут оставаться другие пары, прошедшие только первичный фильтр. Это не разрешение покупать: перед ордером повторно загружается актуальный рынок, проверяются стратегия, комиссии аккаунта, бюджет и риски. Пороговые значения являются начальной инженерной политикой, прибыльность на них не доказана.

Свободный агент выбирает пару по рейтингу и типу стратегии; закрепление минимум 2 часа защищает от постоянных перестановок. Через 6 часов без заявки или при потере допуска монета может смениться. Новая пара не обнуляет P&L, комиссии, возраст и просадку стратегии: проверяется вся стратегия с подбором монет, а не доходность одной выбранной монеты. Назначения записываются отдельно, у каждого ордера сохраняется его исходная пара. Старые эксперименты `fixed-v1` переходят на новый подбор только после освобождения средств, архивируются, а результаты новой политики собираются заново; старые BTC/ETH-результаты не открывают доступ к Live.

Открытая позиция остаётся под наблюдением даже после исключения монеты из рейтинга. У новой политики есть выход через 24 часа; после 6 часов возможен более ранний выход, если монета перестала проходить актуальный отбор. При недоступном стакане или делистинге исполнение невозможно гарантировать. Микроостатки меньше биржевого минимума не списываются и не переименовываются в новую монету: агент остаётся с ними, кабинет сообщает об ограничении. Автоматической конвертации пыли нет. Неизвестный ордер блокирует ротацию до сверки.

При сбое сканирования сохраняется последняя успешная сводка, но покупки запрещены до нового успешного отбора. Просроченный более чем на 10 минут список тоже не разрешает вход. Продажи существующих позиций по свежим стаканам продолжаются. Ошибка одной монеты не мешает выходам по другим; без свежей оценки открытой позиции новые покупки всего её портфеля блокируются.

### Другие способы заработка

В кабинете есть свёрнутая справка о подходах и их фактической поддержке:

- Возврат к средней, тренд и пробой исполняются на споте. Отбор движения ищет условия для этих стратегий; маленькая цена монеты сама по себе не означает больший потенциал.
- Сетка пытается собирать колебания в диапазоне; выход из него оставляет риск по накопленной монете. DCA распределяет покупки во времени, но не гарантирует прибыль. Отдельные grid/DCA-исполнители не добавлены. [Описание сетки Bybit](https://www.bybit.com/en/learn/bybit-trading-bot/what-is-spot-grid-trading-bot).
- Межбиржевой арбитраж требует исполнимого спреда после издержек и контроля обеих сторон сделки; переводы создают дополнительную задержку. Четыре подключения пока независимы. [Обзор арбитража Kraken](https://www.kraken.com/learn/trading/crypto-arbitrage).
- Фандинг сочетает противоположные спотовую и фьючерсную позиции, но ставка может измениться, остаются комиссии и риски маржи. Исполнителя деривативов нет. [Фандинг Kraken](https://www.kraken.com/learn/futures-trading-funding-rate-arbitrage).
- Стейкинг, кредитование и пулы имеют другие источники вознаграждения и требуют отдельного учёта блокировок, контрагентов, контрактов и изменения стоимости активов. Эти интеграции не подключены. [Стейкинг и пулы Kraken](https://www.kraken.com/learn/staking-vs-yield-farming).

Каталоги и тикеры сверены с первичными API: [OKX v5](https://www.okx.com/docs-v5/en/#order-book-trading-market-data-get-tickers), [инструменты Bybit](https://bybit-exchange.github.io/docs/v5/market/instrument), [тикеры Bybit](https://bybit-exchange.github.io/docs/v5/market/tickers), [Binance Market Data](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/market-data-endpoints), [Bitget Market Data](https://www.bitget.com/docs/catalog/market/market-data). У Bybit Spot каталог не использует пагинацию; все четыре адаптера запрашивают полные списки, подробная загрузка свечей ограничена кандидатами.

## Протоколы и оставшаяся приёмка

Нативные TypeScript-адаптеры сверены с первичными источниками: [OKX v5](https://www.okx.com/docs-v5/en/), [Bybit V5](https://bybit-exchange.github.io/docs/v5/guide) и [Demo Trading](https://bybit-exchange.github.io/docs/v5/demo), [Binance Spot](https://developers.binance.com/docs/binance-spot-api-docs/rest-api) и [Testnet](https://developers.binance.com/docs/binance-spot-api-docs/testnet), [Bitget UTA](https://www.bitget.com/docs/uta/quick-start), [управление ордерами](https://www.bitget.com/docs/catalog/trading/order-management) и [коды ошибок](https://www.bitget.com/docs/uta/error-code/restapi). Биржевые правила могут изменяться, поэтому подключение конкретного аккаунта проходит проверки при запуске.

Ранее стаканы и 120 закрытых свечей BTC/ETH получены от всех четырёх публичных API. Новая локальная версия получает полные каталоги USDT и проверяет альткоины; отдельная приёмка зафиксирована в STATUS. Тесты проверяют подписи, разделение ключей и окружений, права, комиссии, частичные исполнения, неизвестные заявки, конкуренцию, распределение бюджета и отсутствие пересечения портфелей. Фактическая проверка приватных Demo/Live API и исполнение на аккаунтах заказчика **ещё требуют его ключей**. Прибыльность и длительная непрерывная работа не подтверждены. Актуальные результаты локальной приёмки — в [STATUS.md](STATUS.md).

Межбиржевой арбитраж, несколько аккаунтов одной биржи и фьючерсное фондирование в эту версию не входят. Четыре подключения работают самостоятельно; автоматических переводов денег и переноса доказательств прибыльности между биржами нет. Из [arb_bot2](https://github.com/Thuser0/arb_bot2) торговый код не переносился.
