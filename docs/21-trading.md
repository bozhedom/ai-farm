# Автономная спотовая торговля

Новый объём согласован владельцем 12.10.2026. Приложение торгует разрешёнными парами на отдельном аккаунте OKX. Средства остаются у биржи. Переводов, вывода, плеча, фьючерсов и хранения приватных ключей кошельков нет. Старые продукты, заказы, стратегии, платежи и аудит сохранены отдельно.

## Режимы и стратегии

- **Бумага:** четыре агента делят виртуальные 100 USDT. Стакан, закрытые минутные свечи и ограничения размера берутся из публичного API OKX. Исполнение проходит по доступной глубине стакана, с неблагоприятным проскальзыванием до 0,1% и комиссией 0,1%. Это симуляция, не доход и не гарантия исполнения на реальном рынке.
- **Демо:** отдельный ключ OKX Demo Trading, настоящие запросы с `x-simulated-trading: 1`, тестовый баланс. Проверочный цикл покупает и продаёт до 10 тестовых USDT, сверяет исполнения и останавливается.
- **Реальные средства:** один агент, до 100 USDT. Допуск требует включения на сервере, явного подтверждения владельца, успешного демо-цикла и бумажного агента с положительным результатом после комиссий, не менее 7 дней наблюдения и 20 закрытых позиций. Ключи бумаги, демо и реального счёта не подменяют друг друга.

Три серверные гипотезы: возврат к средней цене, следование тренду и пробой диапазона. Начальный состав содержит два варианта возврата к средней для BTC и ETH. Все цены сигналов основаны на закрытых свечах и текущем bid/ask. Агент без сигнала ждёт, а не торгует ради активности. Модель в торговом цикле не вызывается, её расходы здесь равны нулю; сервер и другие расходы владельца в P&L не включены.

Каждые сутки система оценивает бумажное поколение. После минимум 7 дней и 20 закрытых позиций у каждого участника сравниваются доходность после комиссий и максимальная просадка. Два лидера должны быть прибыльны, иметь просадку не выше 8% и превосходить следующих участников. При открытых позициях или недостатке доказательств отбор ждёт. Законченное поколение сохраняется в архиве, создаются четыре потомка двух лидеров: два сохраняют параметры, два получают ограниченную мутацию. Капитал поколения сохраняется, статистика потомков начинается с нуля. Это эвристика отбора, не статистическое доказательство будущей доходности.

## Необходимые подключения

1. Собственный аккаунт заказчика на OKX, доступный в его регионе и прошедший требуемую биржей проверку. Для приложения нужен отдельный торговый аккаунт/субаккаунт без ручных сделок, других ботов, займов и деривативов. Режим счёта: Spot или Futures с исключительно cash spot; Multi-currency и Portfolio Margin отклоняются.
2. Отдельные API-ключи Demo Trading и реального аккаунта: чтение и торговля, **без withdrawal**. Реальный ключ обязательно привязан к статическому IP сервера. Право Trade у OKX шире спота, поэтому изоляция аккаунта важна; сам адаптер умеет только перечисленные операции со спотом.
3. Перед первым подключением: BTC и ETH на выбранном торговом аккаунте равны нулю, свободно минимум 100 USDT. На демо счёт пополняют тестовыми средствами. Реальный счёт пополняет сам владелец; USD и USDT не тождественны. Остаток USDT свыше 100 фиксируется отдельно и не увеличивает бюджет агента.
4. Ключи записываются локально в `.env` или секреты сервера, не в браузер, Git или чат:

```dotenv
WORKSPACE_MODE=trading
OKX_API_HOST=openapi.okx.com
OKX_DEMO_API_KEY=
OKX_DEMO_SECRET=
OKX_DEMO_PASSPHRASE=
OKX_LIVE_API_KEY=
OKX_LIVE_SECRET=
OKX_LIVE_PASSPHRASE=
TRADING_LIVE_ENABLED=false
```

Хост выбирается по региону регистрации аккаунта: глобальный `openapi.okx.com` (также поддерживается `www.okx.com`), США/Австралия `us.okx.com`, ЕЭЗ `eea.okx.com`. Подмена домена для обхода ограничений не реализована. Доступность USDT-пар и Demo Spot зависит от аккаунта; отказ API останавливает запуск.

После изменения окружения пересоздайте web и worker. Миграции применяются штатным `npm run db:migrate` или при старте контейнера web. `WORKSPACE_MODE=trading` отключает расписание и запуск исследовательских заданий старой студии; принятые заказы продолжают обрабатываться. `WORKSPACE_MODE=studio` возвращает прежний обработчик. История не удаляется.

Проверка подключения **без ордеров**:

```bash
npm run trading:check
npm run trading:check -- demo
npm run trading:check -- live
```

## Исполнение и учёт

Суммы передаются десятичными строками. В расчётах используются BigInt с 18 десятичными знаками, в PostgreSQL целые `numeric(60,0)`. Копейки старого продукта и тестовый ETH не смешиваются с USDT. Комиссия учитывается в фактической валюте каждого исполнения; неподдерживаемая валюта или неполная история исполнений блокируют дальнейшие ордера.

Реальные ордера только `tdMode=cash`, `ordType=ioc`, с предельной ценой. Неисполненный остаток отменяется биржей. Максимум входа 10 USDT; выход может закрыть всю имеющуюся позицию, даже если она подорожала. До 50% капитала в позициях, не более 40 заявок за сутки для входов; защитные выходы не блокируются этой квотой. Минимум входа 5 USDT плюс фактический шаг/минимум инструмента. Интервал между обычными сделками агента 5 минут, защитный выход выполняется без ожидания. Проверка рынка примерно раз в 15 секунд.

Перед каждым ордером сервер фиксирует намерение и уникальный `clOrdId`, который не используется повторно даже после отмены. Блокировка PostgreSQL разрешает только один незавершённый ордер на портфель, включая несколько worker. После неопределённой отправки приложение проверяет биржу по сохранённому ID, **не отправляет заявку заново**. Частичное исполнение учитывается и при отменённом IOC. После потери ответа требуется явное возобновление владельцем даже при успешной сверке.

Сверка проверяет привязку к аккаунту, все собственные USDT/BTC/ETH и отсутствие сторонних заявок. Ручная сделка, перевод, пополнение после инициализации или смена аккаунта остановят торговлю с объяснением. Не меняйте баланс работающего выделенного аккаунта. Разница больше 0,000001 USDT или 0,000000000001 BTC/ETH считается расхождением. История и стартовый бюджет не сбрасываются для устранения ошибки.

## Остановка и восстановление

- **Пауза входов:** новые покупки запрещены, уже открытые позиции продолжают контролироваться по стопу и фиксации прибыли.
- **Закрыть позиции:** покупки запрещены, worker продаёт доступные позиции по ограниченным ценам. Это не обещание немедленного полного исполнения; минимальные остатки меньше лота/минимума остаются видны.
- **Аварийный стоп:** новые заявки запрещены. Уже зафиксированный к отправке запрос может завершиться; его результат будет сверен. Открытые активы остаются на бирже и продолжают менять стоимость.
- Дневной убыток 2% и просадка от пика 10% включают закрытие позиций. Стоп позиции 3%. Это пороги реакции, **не гарантированный предел потерь**: цена, простой сервера, проскальзывание и доступность API могут дать больший убыток. Нативного биржевого стоп-ордера в этой версии нет.
- Возобновление не обнуляет пик, комиссии, дневной результат и историю. Дневной лимит ждёт новых UTC-суток. Общая просадка блокирует повторный запуск этого эксперимента; автоматического сброса бюджета нет.
- Если отправленный ордер не найден, приложение ждёт ручной проверки. Владелец проверяет `clOrdId` в истории биржи; подтверждение отсутствия возможно не ранее минуты после отправки, только при повторном отсутствии ордера, чистом списке открытых заявок и совпадающем балансе. Подтверждение сохраняется в аудите, исходный ID не переиспользуется.
- После восстановления старой копии БД реальные деньги не включайте до сверки с биржей: в копии могут отсутствовать уже отправленные заявки. Сначала режим остановки/отключённый live, проверка истории и баланса. Ключи и данные заказчиков требуют отдельного защищённого резервирования.

## Основание интеграции и границы приёмки

Нативный TypeScript-адаптер использует [официальный OKX API v5](https://www.okx.com/docs-v5/en/) и [правила исполнения заявок](https://www.okx.com/docs-v5/trick_en/). Сверены аутентификация, региональные домены, демо-заголовок, cash IOC, `expTime`, комиссия, клиентский ID и история исполнений. Уникальность `clOrdId` биржа гарантирует только среди текущих заявок; приложение обеспечивает уникальность за всю собственную историю.

Из [arb_bot2](https://github.com/Thuser0/arb_bot2) код не скопирован: он не предоставляет необходимый надёжный учёт ордеров. Межбиржевой арбитраж и фьючерсное фондирование в этот продукт не входят. Для небольшого бюджета выбран один спотовый аккаунт без переводов между биржами.

Публичный API BTC/ETH проверен из среды разработки. Автоматические тесты проверяют денежную точность, протокол адаптера, потерю ответа, восстановление, конкуренцию, лимиты, сверку, эволюцию и отдельный демо-цикл. Настоящие приватные запросы Demo/Live, исполнение на аккаунте заказчика, доступность его региона и длительное наблюдение требуют его доступов. Прибыльность не подтверждена; бумажные результаты не подменяют биржевую приёмку.
