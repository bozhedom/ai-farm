## Серверные правки по сквозному QA (09.10)

- Оплата ([18-crypto-payments.md](18-crypto-payments.md)): hash, которого узел не показал (опечатка), больше не блокирует сканер; найденный перевод точной суммы его заменяет (`payment_hash_replaced`). - Тексты модели для людей проверяет сервер (`textQualityIssue` в `core/policy.ts`): страница продукта, контрольный пример, отклики, отчёт руководителя, язык результатов заказов. Запрещены иероглифы и другие письменности, латиница внутри русского текста (кроме брендов, форматов и слов из исходника), служебные слова, две точки, обрывы; длинное тире сервер меняет на дефис. - Неудачная сборка по идее: продукт не выходит, идея получает «нужен человек» и причину в `ideas.build_error` (миграция 025), событие `idea_build_failed`.

Примеры: до проверки языка в схеме 2 из 5 содержали английские слова («originals», «catalogs»), после неё 4 из 4 прошли. Страницы: 7 из 10 вышли, 2 раза модель при исправлении заголовка сломала ответ (сборка в чужой для идеи тип, отказ правильный по сути), 2 отказа по прежнему стоп-листу содержания. ## Реализовано и проверено

- Общий мастер-промпт для каждого модельного вызова, узкие роли, JSON-схемы, проверка текстов и ограниченные инструменты.
- Автономное суточное исследование, отдельный критик, сборка конфигураций до трёх текстовых сервисов. Контрольный ввод, короткий ввод и известная prompt-injection проверяются до выпуска.
- Серверные рецепты явно задают результат каждого шаблона для исследования, исполнения и QA. Контрольные материалы различаются для описания, FAQ и публикаций; причина отклонения контрольного примера сохраняется в гипотезе. Поле оценки расходов объяснено также в JSON-схеме, без снижения или подмены модельной оценки.
- Исполнитель и проверяющий получают факты из материала заказа; название и аудитория сервиса из каталога исключены из их контекста. Описание товара ограничено кратким списком исходных характеристик; проверка отдельно требует сохранять отрицания и не считать правдоподобные выводы исходными фактами.
- Общая память последних выводов без данных заказчиков. Задание сохраняет состав шаблонов и стратегию для продолжения после сбоя.
- Подключены OpenAI / GPT-6 Astra и SearXNG. Ответы валидируются по строгой схеме, все роли используют master. Нет автоматических платных повторов, удалённых инструментов или сохранения диалогов у провайдера. Ollama остаётся альтернативой; Yandex реализован, но его живой API не проверен.
- Дополнительный кеш прошлых промптов llama-server отключён: стандартные 8 GiB превышали 6 GB контейнера и привели к OOM на длинной серии ролей. Лимиты ресурсов и том модели сохранены; применяется `LLAMA_ARG_CACHE_RAM=0`.
- Пульт показывает роль, стратегию, задачу, время, историю этапов, токены, фактическую стоимость по usage и отдельный резерв. При OpenAI счётчики появляются после ответа; для Ollama доступны потоковые символы. Гипотезы показывают исходную модель и выпущенную версию сервиса. Простой / потеря связи отделены от работы; обновление раз в две секунды.
- Анимации отражают выбранное задание и активный вызов; при потере связи и reduced motion движение прекращается. Видны найденные ссылки, проверенная гипотеза до конца цикла и отдельный критик. Токены берутся из ответа провайдера, старые неизвестные значения не выдаются за ноль.
- Worker перед взятием локальной задачи проверяет готовность Ollama / SearXNG. При недоступном поиске исследование ждёт без расхода попыток; готовая модель может выполнять заказы.
- Ручные исследования без суточной квоты и задержки между завершёнными заданиями. Параллельные нажатия используют одно задание; счётчик запусков виден в панели. Бюджеты, пауза, аварийный стоп и окно исследований сохраняются.
- В пульте можно выбрать направление исследования: описание товара, FAQ, публикации или автоматическое чередование. Выбор сохраняется в задании, а повторное нажатие не меняет уже запущенный план.
- При ошибке формата допустима одна локальная попытка исправления; денежные оценки этим механизмом не корректируются. Превышение бюджета сохраняется в гипотезе и запрещает выпуск. Кеш демопровайдера нельзя выдать за живой ответ после смены провайдера.
- Новая принятая гипотеза может обновить версию существующего продукта. Полная история версий и старые снимки заказов сохраняются. На карточке доступен контрольный результат.
- Направления исследований чередуются по времени последней попытки поиска, включая неудачные запуски без сохранённой гипотезы. Отсутствующий продукт после отказа не блокирует изучение и обновление остальных шаблонов.
- Постоянная очередь PostgreSQL, идемпотентные задания, аренда задачи / heartbeat, ограниченные повторы. Устаревшие суточные задания пропускаются после паузы, чтобы не запускать накопившиеся расходы.
- Отдельные циклы исследования, обработки заказов и сверки платежей внутри worker.
- Разделы панели вынесены в `app/components/dashboard/`, обработчики заданий — в `core/jobs/`, провайдеры — в `core/providers/`. [Карта проекта](06-project-map.md) объясняет, где менять поведение и запускать проверки.
- Общий дневной и месячный бюджет, защищённая часть для заказов, атомарные резервы, консервативный учёт неизвестного исхода API-вызова. Дополнительный общий предел OpenAI в микродолларах не обнуляется со сменой дня или месяца; проверяется в той же транзакции. Кеш и рассуждение учитываются без двойного списания.
- Вход владельца с серверной сессией, ограничение попыток, проверка Origin, закрытые API, лимиты размера ввода, сохранение версии продукта и стратегии в заказе.
- Русскоязычная адаптивная панель, гипотезы и источники, стратегии, тестовая витрина, заказы, журнал, расходы и TXT-выдача.

- Sepolia: адаптер read-only RPC, точная сумма wei, hash, сеть, получатель, статус, время счёта, canonical block, подтверждения и защита от повторного использования транзакции. **Проверен на моделируемых RPC-ответах, не на реальном переводе.**
- Недельный отчёт HOLD без реальной выручки. Через 28 дней без подтверждённых продаж исследования останавливаются; заказы сохраняются. Новое окно открывает владелец.

- Мягкая пауза, аварийный стоп, сохранение оплаты при остановленном worker и выдача после его запуска.
- Docker Compose, healthcheck локального стека, ежедневные копии, ручной backup и восстановление. На VPS работает Caddy с действительным HTTPS, подготовлен запуск заранее собранного образа без сборки на небольшом сервере.
- GitHub Actions: форматирование, TypeScript, модульные и интеграционные тесты, production build.

## Сохранённое решение по облачному стенду от 01.10

Сервер, SSH и рабочий API-ключ уже предоставлены; повторно их не запрашивать. Дальше выбрать постоянный бюджет и материалы для оценки качества. До этого оставить паузу, выключенное расписание и предел $1. Для просмотра сохранённых результатов новые расходы не нужны.

Живая приёмка публикаций с рабочей моделью и платное расписание — только после разрешения расходов; внешнее наблюдение и копия вне VPS остаются открытыми. Живой выпуск публикаций и реальный Sepolia-перевод непроверены. Реальные продажи — отдельный этап.
