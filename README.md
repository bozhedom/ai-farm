# AI Farm

Автономная торговая ферма для спота OKX, Bybit, Binance и Bitget. Четыре агента проверяют стратегии на реальном рынке с виртуальным капиталом; отбор сохраняет лидеров и создаёт варианты их параметров. После бумажной проверки и демо-сделок один отобранный агент на каждой подключённой бирже получает бюджет, заданный владельцем.

**Начать здесь: [подключение бирж, управление и ограничения](docs/21-trading.md).** Фактически выполненные проверки и оставшиеся условия приёмки: [STATUS.md](docs/STATUS.md).

**На сервере: [торговый кабинет](https://farm.45.114.60.6.sslip.io/office/trading).** Обновлён 12.10.2026, пароль владельца прежний. Запущена тренировка четырёх бирж; реальные заявки выключены. [Эксплуатация сервера](docs/10-cloud-vps.md).

## Запустить локально

Нужны Node.js 24 и Docker Compose. Для торгового контура не нужны модель, поисковый API или платная подписка.

```bash
npm ci
npm run setup
docker compose --profile app up -d --build
```

Откройте **http://localhost:3210**. Пароль владельца находится в поле `OWNER_PASSWORD` локального `.env`. После входа откроется торговый кабинет. Выберите «Тренировка» и нажмите «Запустить тренировку»: начнут работать 16 агентов на четырёх биржах, с виртуальным бюджетом по 100 USDT на биржу. Для запуска одной биржи откройте её строку и нажмите «Запустить». Браузер можно закрыть; сервер и worker должны продолжать работать.

`setup` сохраняет существующие настройки. По умолчанию `WORKSPACE_MODE=trading`, реальные заявки отключены. Не запускайте `local:setup` ради торговли: эта отдельная команда устанавливает Ollama для прежней текстовой студии и переключает её модель.

## Что умеет приложение

- Единый кабинет четырёх бирж: отдельные бумага, Demo/Testnet и реальные средства с независимыми журналами и ключами.
- Динамический отбор ликвидных USDT-пар; возврат к средней, тренд и пробой диапазона. Дополнительный тренировочный набор с ограниченными grid/DCA. Автоматический отбор и архив поколений; смена реального агента только без открытой позиции.
- Точный учёт сумм, исполнений, комиссий, стоимости открытых активов и просадки. Моделей в цикле сделок нет.
- Лимит входа 10 USDT, до 50% капитала в позициях, реакция на дневной убыток 2%, просадку 10% и стоп позиции 3%.
- Кабинет с графиком капитала, агентами, сделками, CSV, журналом событий, проверкой подключения, паузой, закрытием позиций и общим стопом.
- Сверка с биржей и восстановление после сбоя без повторной отправки неизвестного ордера. Плечо, вывод и переводы не реализованы.

Для реального режима нужны выделенные аккаунты выбранных бирж, выбранный владельцем бюджет (от 20 USDT на биржу), отдельные Demo/Live API-ключи без вывода и статический IP сервера. Пример со 100 USDT не ограничивает реальные суммы. Ключи хранятся в окружении сервера. Допуск требует минимум 7 дней и 20 закрытых бумажных позиций у прибыльного кандидата, успешного демо-цикла и явного включения владельцем. Эти условия могут занять больше семи дней или не выполниться.

Прибыльность не подтверждена. Пороги риска запускают защитную реакцию, но не гарантируют максимальный убыток при разрыве рынка или недоступности сервера/биржи. Приёмка приватных Demo/Live API требует настоящего аккаунта; публичные данные и автоматические сценарии проверены отдельно.

## Прежняя студия

Локальные новые направления находятся в **`/office/earnings`**: сравнение цен бирж, публичный фандинг, события Polymarket/Kalshi, пулы DeFi и проба API текстовых услуг. Мониторинг не отправляет заявки и не переводит деньги. Grid/DCA работают только на бумаге; x402 и исполнители других рынков пока не реализованы. [Фактические возможности, архитектура и требования к заказчику](docs/25-earning-workspace.md).

История текстовых продуктов, заказов, стратегий, тестовых платежей и аудита сохранена. Витрина доступна по `/storefront`, прежний кабинет — по `/office`. Режим `trading` отключает исследовательские задания студии и продолжает выполнять уже принятые заказы. `WORKSPACE_MODE=studio` возвращает её расписание. Sandbox и Sepolia остаются тестовыми платежами, не выручкой.

Руководства студии: [возможности](docs/16-plain-guide.md), [доставка текстовых услуг](docs/15-delivery-and-business.md), [OpenRouter](docs/13-openrouter.md). Они описывают прежний продукт, отдельно от спотовой торговли.

## Разработка и проверка

Команды настройки базы, worker, резервирования и восстановления: [инструкция запуска](docs/03-setup.md). Значимые изменения проверяются командами:

```bash
npm run typecheck
npm test
npm run test:integration
npm run build
npm run format:check
npm run test:e2e:office
```

Integration требует отдельной базы с суффиксом `_test`. Проверка биржевого подключения без заявок: `npm run trading:check -- paper bybit` (также `okx`, `binance`, `bitget`), затем при наличии ключей `npm run trading:check -- demo bybit` или `-- live bybit`.

Архитектура: [план](docs/01-project-plan.md), [карта проекта](docs/06-project-map.md), [правила моделей](prompts/master.md). Первоначальные DOCX сохранены как исходные материалы; актуальный торговый объём описан в [21-trading.md](docs/21-trading.md).

Торговый LLM-менеджер: `/office/manager`. Сам ставит и проверяет ограниченные Paper-эксперименты; не включает Live и не снимает стопы. Подключение, бюджет и границы: [26-trading-manager.md](docs/26-trading-manager.md).
